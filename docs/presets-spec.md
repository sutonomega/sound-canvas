# v1.1 設定プリセット仕様

対応: [#45](https://github.com/sutonomega/sound-canvas/issues/45)、[M5](https://github.com/sutonomega/sound-canvas/milestone/5)、親Issue [#22](https://github.com/sutonomega/sound-canvas/issues/22)。**これは次期機能の仕様で、v1.0.0には未実装。** 本書のdev統合後に実装へ進む。期限は設定しない。

## 目的と優先順位

気に入った色や動きを、再読み込み後や別の曲でも呼び戻せるようにする。既存の5項目の設定と復元処理を再利用でき、音源・動画処理へ新しい依存を追加しないため、最初の拡張に選ぶ。

| 候補 | 今回の扱い・理由 |
| --- | --- |
| 名前付き設定プリセット | M5で実施。既存設定を再利用する小さな制作支援機能 |
| 曲名・アーティスト名 | 次候補。表示位置・文字・保存映像への合成を別途設計 |
| 短尺切り抜き | 次候補。開始／終了指定、音声・描画の時間基準を別途設計 |
| MP4 | 調査を別途実施。対応環境・音声付き出力・追加処理の負担を評価してから採用 |
| 複数スタイル合成・歌詞・サビ演出 | #22に保持。描画・時間制御・入力仕様への影響が大きいため今回へ含めない |

未着手の機能の公開時期や順序を確約しない。v1.0の不具合修正が必要になった場合は、拡張と独立したIssue／PRで扱う。

## 保存する内容

| 項目 | 値 |
| --- | --- |
| スタイル | `organic` / `geometric` / `particles` / `watercolor` |
| テーマ | `aurora` / `ember` / `ocean` |
| 反応の強さ | 25〜200の整数（画面の%値）。適用時に100で割る |
| 軌跡 | `accumulate` / `fade` |
| 比率 | `portrait` / `landscape` / `square`。寸法は既存の定義から取得 |

音源、ファイル名、曲名、音声の解析値・シード・識別値、再生位置、描画状態、PNG／WebMは保存しない。ID・プリセット名・5項目の設定だけを保存する。名前は利用者が入力するため、機密情報や曲名を避ける案内を出す。

保存は明示操作のみ。初回に既定プリセットを作らず、最後に使った設定を自動適用せず、起動時の既存の初期設定を維持する。

## 保存データと境界

`localStorage`の専用キー`sound-canvas:presets:v1`に、次の形式をJSONで保存する。

```json
{
  "version": 1,
  "presets": [
    {
      "id": "opaque-stable-id",
      "name": "深海の光",
      "settings": {
        "style": "organic",
        "theme": "ocean",
        "strength": 100,
        "trail": "accumulate",
        "ratio": "portrait"
      }
    }
  ]
}
```

- 最大20件。保存順で表示し、上書きで順序を変えない。
- 名前は前後の空白を除去しNFC正規化して1〜40 Unicodeコードポイント。改行・制御文字は受け付けない。同じ正規化済みの名前は重複不可。大文字小文字は区別する。
- 新規保存は新しい一意IDを割り当て、上書きは対象ID・名前を維持する。名前変更は初版の対象外。IDは描画乱数へ渡さない。
- 保存文字列はUTF-8換算64KiB以内。読込時もサイズを先に確認し、JSON解析・全項目・件数・ID重複・名前重複を検証する。
- 未知の版、未知のキー、未登録スタイル／テーマ、範囲外・非整数・非有限の強さ、不正比率・軌跡は不正データとして扱う。無効な行だけ消して上書きする処理は行わない。
- 新しい有効な値を構築してから保存し、`setItem`成功後に画面側の保存済み一覧を更新する。保存時点の確定したrenderer設定を使い、スライダー操作中の未確定値は保存しない。

将来のデータ移行はその版で設計する。現時点で不明な版を既知の形式へ自動変換しない。

## 画面の流れ

キャンバス設定欄に「設定プリセット」を追加する。主な操作はプリセット一覧、名前入力、「現在の設定を保存」「適用」「この設定で上書き」「削除」。初回は「保存したプリセットはありません」と案内する。

1. **新規保存**：設定を決めて名前を入力し、保存する。選択済みのプリセットがあっても新規操作で上書きしない。同名・上限超過は理由を表示する。
2. **適用**：一覧の選択だけでは設定を変えず、「適用」で5項目を一括反映する。停止中なら停止を維持し、再生中なら既存のconfigureと同様に復元後の再生意図を保つ。新たな曲読み込みや停止中からの自動再生は行わない。
3. **上書き**：対象を選び「この設定で上書き」で対象名と確認・キャンセルを表示する。確定時の現在設定を保存し、明示確認前に変更しない。
4. **削除**：対象名と確認・キャンセルを表示し、確定時にその1件だけを削除する。現在の設定・プレビュー・曲・生成済み成果物は変更しない。

上書き／削除の確認は欄内の確認領域で行い、操作対象が変わったときは確認を解除する。成功・中止後に適切な操作へフォーカスを戻し、失敗時は入力を保って理由を通知する。名前はHTMLとして解釈せず`textContent`等で表示する。

選択と現在設定を区別する。適用後に手動設定を変更した場合は「現在の設定は選択したプリセットと異なります」と案内する。名前やIDから現在設定を推定しない。

## 制作処理との統合

- 有効な5項目を検証し、既存の`StudioController.configure(settings, [width, height])`へ一度で渡す。5回の個別変更・復元は行わない。
- 既存の設定表示はrendererの確定状態から更新する。プリセット用に第2の描画設定を持たない。
- 同じ設定の適用は既存の無変更判定を再利用し、再描画しない。
- 復元中の再適用は既存の「最後の操作を反映」を使う。復元完了前に「適用が完了しました」と通知しない。設定が反映されても復元に失敗した場合は、その状態と再試行方法を明示する。
- 復元の中止は既存の「中止して最初に戻る」で、適用された設定の曲頭へ戻る。プリセット保存データを変更しない。
- 曲なしでも設定を適用・保存できる。次に読み込む曲へ反映する。

| 状態 | プリセット操作 |
| --- | --- |
| 通常・停止・曲なし | 一覧選択、保存、適用、上書き、削除が可能 |
| 通常再生中 | 同上。適用は既存の再生意図を維持 |
| シーク／設定の復元中 | 一覧選択と適用は可能。新規保存・上書き・削除は復元完了まで無効 |
| 音源読込・再生開始処理・PNG／MV処理（終了・復元も含む） | プリセットの変更操作を無効化し理由を表示。保留操作を後から自動実行しない |
| 保存領域の異常 | プリセット操作を制限し、通常の設定変更・再生・保存は継続可能 |

確定前に状態を再確認し、復元・読込・出力が始まった場合は古い確認で保存／削除しない。プリセット操作で既存のPNG／MVの結果を消さず、出力後の設定変更で既存成果物の説明を取り違えない。出力中は引き続き設定を固定する。

## 保存失敗・破損・複数タブ

`localStorage`へのアクセス自体も例外を捕捉する。利用拒否・容量不足等で保存できない場合は「このブラウザではプリセットを保存できません」と案内し、保存成功の表示や無通知のメモリ保存へ切り替えない。書込失敗時は直前の一覧を保持する。

破損・未知版・サイズ超過時は勝手に初期化・上書きしない。通常制作を継続できるようにし、保存変更を止める。「プリセット保存データを初期化」で対象と消去の意味を説明し、確認／キャンセル後に専用キーだけを削除できるようにする。他アプリも使う`localStorage.clear()`は使用しない。初期化成功後に空一覧を反映する。

同じ保存先を別タブが更新した場合、`storage`イベントで一覧を再読込し、進行中の確認を解除する。適用中の映像設定は勝手に変えない。書込直前にも保存文字列を読み直し、最後に表示したデータと異なる場合は操作を中断して再読込・再確認を促す。削除対象が消えていた場合に別の行へ作用しない。

localStorageには複数タブの完全なトランザクションを提供する仕組みを追加しない。ほぼ同時の書込は最後の書込が残り得るため、初版では一つのタブで編集することを案内する。完全な同時編集保証は対象外。

保存先はブラウザ・プロファイル・オリジンごとで、端末間同期やGitHubアカウント同期はない。ブラウザのデータ削除やプライベート閲覧で消えることがあるため、作品の永続バックアップとは説明しない。公開サイトとローカル起動は別の保存先として扱う。

参考: [MDN localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)、[storageイベント](https://developer.mozilla.org/en-US/docs/Web/API/Window/storage_event)。保存領域の可用性や上限を固定値で保証せず、64KiBはアプリ側の受け入れ上限とする。

## 責務と確認

保存・検証モジュールとUIの接続を分ける。保存先を注入して単体確認できる構成にし、レンダラー・音楽解析へ保存APIを持ち込まない。

保存基盤では正常往復、全境界、未知の値・版、不正JSON、保存API例外、上限、表示後の外部更新を検証する。UIでは別曲・再読み込み、保存拒否、破損復旧、複数タブ、操作の連打・復元・出力との競合、入力中のフォーカスを確認する。適用と同じ手動設定で、同じ曲・時刻の画素が一致するか比較する。

通常Windows Chrome／Edgeで設定保存・再読み込みと主要操作を確認し、PNG・短いWebMを実保存して再生する。実施範囲と未確認は区別する。公開後の同操作とCI・Pages成功を確認してからv1.1.0タグ／Releaseを作成し、M5を閉じる。今回の仕様PRではアプリの版を変更しない。
