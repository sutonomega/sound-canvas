# Issue #19：操作・キーボード・日本語表示

2026-11-13、Windowsのアプリ内Chrome系ブラウザで、同梱36秒デモと1秒の合成WAVを使って確認した。実音源の追加使用はない。画面操作・DOM観測・保存ファイルの検査を組み合わせ、スクリーンリーダーの実機評価や完全なアクセシビリティ適合審査とは区別する。

## 改善

- 曲選択inputの`display:none`をやめ、Tabで到達できる見た目上の非表示に変更。親の選択欄全体へフォーカス枠を表示し、一定の日本語名を付けた。マウスでは選択欄を押して同じダイアログを開ける。
- 初回は「先に楽曲を読み込むか、デモを体験してください」、解析・描き直し・再生準備・PNG/MV処理中はそれぞれ保存を待つ理由を表示。保存ボタンを共通の説明に関連付けた。同じ理由を複数の出力説明へ重複表示しない。
- 読込完了後の再生、出力開始時の中止、成功後の保存リンク、中止後の再試行へフォーカスを接続。利用者が別の場所へ移動した場合は奪わず、設定変更やシークの描き直し中も有効な入力欄に留まる。
- シークは矢印で1秒、Shift＋矢印とPage Up / Downで10秒移動。曲頭/曲末で止める。Home/Endは標準の操作を維持し、マウスの細かな指定も維持する。読み上げ用の値に日本語の分・秒を付け、同じ文字列を毎フレーム更新しない。
- 設定欄への移動リンク、プレビューの名前、画面上のキー操作説明を追加。比率の選択には色に加えて✓を表示し、既存の押下状態の属性も維持。
- 説明文字を大きくし、文字・ボタン枠・無効表示の見やすさを調整。狭い画面で列・スライダー・説明を縮めたり折り返したりできるようにした。

## 実際の操作結果

| 確認 | 結果 |
| --- | --- |
| 初回の保存ボタン | 無効理由とデモ/曲選択への案内を表示 |
| Tab→デモ→Enter | 読込・解析後に再生ボタンへフォーカス |
| Spaceで再生/停止、矢印でシーク | 成功。1秒→Shiftで11秒→Page Downで1秒→Endで36秒。フォーカスはシークに保持 |
| Tabで曲選択、Space | 選択ダイアログの起動と短WAVの読込が成功。ダイアログ内のファイル指定はツールのファイル指定機能を使用 |
| キーボードで設定変更 | 幾何学、Ocean、反応101%、減衰、16:9へ変更できた。ネイティブの選択候補はEscapeで閉じてからTabで移動 |
| PNGのEnter操作 | 生成開始で中止、完了後は保存リンクにフォーカス。Enterで保存操作ができた |
| 36秒のMVをキーボードで録画 | 中止ボタンへフォーカスし、完了後は保存リンクへ移動。元の36秒位置へ停止復帰 |
| MVのキーボード中止 | 中止→途中動画なし→録画開始ボタンへフォーカスが戻り、再試行できる |
| 破損WAV | 日本語の読込エラーを表示し、前のデモを保持。再生操作が再び有効になった |
| マウスの制作フロー | 選択欄から短WAVを読み、再生/停止、粒子/1:1への変更、完成PNGとMVの生成・保存リンク操作が成功 |
| 実ファイル保存の追試 | Enterでリンクを操作して完成PNG 400,369バイト（720×1280）とWebM 257,405バイトを保存。PNGヘッダーとVP8映像/Opus音声トラックを確認 |

UIの保存リンク操作と、ツールからダウンロードファイルを受け取る確認を分けた。最終の実ファイル追試は1秒の合成WAV・有機的曲線・9:16を使用。36秒MVや粒子PNGのリンクを押した事実だけで、それらのディスク保存を完了扱いにはしていない。保存した音源・動画はリポジトリに追加していない。
