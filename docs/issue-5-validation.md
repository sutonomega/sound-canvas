# Issue #5：読み込み・再生の状態管理と確認

## 変更した動作

- 候補音源はデコード・解析が成功してから確定する。失敗・中止時は前の楽曲と位置を保持し、描画を復元して停止する。
- 読込中も別ファイルを選べる。解析進捗と「読み込みを中止」を表示する。
- AbortControllerと処理世代で、古い読込・進捗・エラー・描画復元を無効化する。ブラウザ内部のデコードやファイル読取自体は強制終了できないが、完了した古い結果は確定しない。解析・デモ生成の分割処理は中断する。
- 再生中の連続シーク・設定変更では元の再生意図を最後の復元まで引き継ぐ。最初に戻る、曲差替え、読込中止は停止状態にする。
- AudioContextの再開待ちの間に操作が変わったら、古い再生要求で音を開始しない。曲末へのシークは先頭へ戻さず停止する。
- 自然終了した音声ノードを切断する。曲末から再生すると音と描画を0秒へ初期化する。
- 曲末の端数区間も描画する。描画が追いつくまでPNG保存を無効にする。

`dist/controller.js` が状態・処理世代・再生意図を持ち、`audio.js` は候補の準備と確定を分離した。帯域推定・ビート検出等の方式は今回変更せず、Issue #6で改善する。

## 自動確認

2026-11-12、Windows上のNode.jsで `npm test` を実行。20件成功、失敗なし。

実AudioContextの代わりに制御可能な音声ノードを使い、順序が逆転する非同期処理を確認する。解析成功・解析中断は合成PCMで確認する。

- 連続選択で古いデコードが後から完了しても最後の音源を採用
- 古い進捗・エラーが新しい結果を上書きしない
- 読込失敗・中止時の前曲・位置・描画の復元、初回失敗後の再読込
- 再生中の連続シーク・設定変更、新曲読込・最初に戻るによる復元中断
- AudioContext再開待ちの無効化、再開失敗後の再試行
- 曲末の端数フレーム、曲末からの再生、曲末へのシーク
- 自然終了時の切断、古い終了イベントの無効化、音声開始失敗時の後始末
- 範囲外シーク、デコード/解析の中断、解析成功時の候補保持
- 復元中・描画追従中のPNG操作制御

構文チェック、差分の空白チェックも行う。GitHub Pages公開時のワークフローにも同じ状態管理テストを追加する。PR時のCI全体整備はIssue #21の範囲。

## ブラウザ確認

2026-11-12、WindowsのCodex内ブラウザ、ローカルHTTP配信で確認（ブラウザ版番号は未取得）。ユーザーの音源は使わず、8kHz・16bit・モノラルの合成正弦波WAVと、音源ではない内容の `broken.mp3` を使用した。素材はリポジトリに追加しない。

| 確認 | 結果 |
| --- | --- |
| 約2.11秒のWAV読込・再生 | 解析完了、再生時刻が進行 |
| 曲末と再再生 | 完成表示後、再生操作で0秒へ戻って再生 |
| 壊れたMP3選択 | エラー表示、前のWAV名・曲長を保持し操作可能 |
| デコード中の中止 | 中止表示、前の曲を保持 |
| 約9.03秒の別WAVへ差替え | 新曲名・長さに切り替わり再生可能 |
| 再生中に6秒→2秒へシーク | 最後の位置へ復元し、再生継続 |
| 最初に戻る | 0秒・停止へ戻る |
| 5分のWAV解析 | 解析率表示を確認し、解析完了まで処理 |
| 5分のWAVを再選択して解析途中で中止 | 中止表示、確定済みの前曲を保持し操作可能 |

## 未確認・対象外
