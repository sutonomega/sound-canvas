# Sound Canvas：v1.0設計

対応Issue: [#3](https://github.com/sutonomega/sound-canvas/issues/3)。[仕様書](spec.md)を実装するための目標設計。0.1では実装を少数のモジュールに集約していた。devではM2/M3で下記の分離構成へ移行済みで、各節に実装上の契約と検証記録を記載する。開発・公開の操作は[開発ガイド](development-and-release.md)を参照。

## 構成と依存方向

```text
UI → 制作コントローラー → AudioEngine / Analyzer
                      → RenderEngine → Style
                      → ExportController → RenderEngine / AudioEngine
```

| 部分 | 責務 | 扱わないもの |
| --- | --- | --- |
| UI | ファイル選択、設定、状態・進捗、保存操作 | 音の解析・スタイル固有の計算 |
| 制作コントローラー | 状態遷移、操作の排他、世代管理、復元・中止 | Canvasの個別表現 |
| AudioEngine | デコード、音声ノード、音声時計、再生位置 | DOMと描画 |
| Analyzer | AudioBufferから全曲特徴・シード生成 | 再生状態、録画、スタイル |
| RenderEngine | 固定刻み、3層合成、スタイル呼出、状態保存 | 音源ファイル・音声時計の取得 |
| Style | 特徴値に応じた描画と内部状態 | DOM、ファイル読込、AudioContext |
| ExportController | 録画準備/終了/中止、PNG生成、資源の後始末 | 個別スタイルの再実装 |

当面はビルド不要のESモジュールを維持し、上記は責務単位として段階的に分割する。ファイル名を先に大量作成することを目的にしない。共通基盤にはスタイル名による条件分岐を入れず、登録表から選択する。将来の同時合成を妨げない境界にするが、v1.0の有効スタイルは常に一つ。

## 解析データ契約

```text
Analysis {
  version, trackKey, seed, sampleRate, sampleCount, duration,
  featureRate: 30,
  frames: [{ volume, bass, mid, high, beat, intensity }]
}
```

framesは時刻 `k/30` から `min((k+1)/30, duration)` の入力区間に対応する。個数は境界補正後の `ceil(duration*30)`。各連続値は有限の0〜1、beatはその区間のイベントを示す真偽値。曲末を超える参照は最後の値を無限に繰り返さず、曲末で更新そのものを止める。無音の正規化基準には下限を設ける。左右の波形を先に平均せず、チャンネル別の帯域エネルギーを統合する。

解析版に帯域境界、正規化、平滑化、ビート間隔、intensity推定の方式を対応付ける。`sc-analysis-3` の確定値は[仕様書の解析方式](spec.md)に記載する。平滑化は全曲解析時に一度だけ実施し、個別スタイルがフレームレート依存の平滑化を重ねない。

`trackKey` は音源内容を識別し、ファイル名には依存しない。内容識別の強いハッシュと描画用の32bitシードは役割を分け、同一シードだけで別曲のキャッシュを共有しない。解析結果は読込成功時に一括で確定し、失敗時に現在の曲を壊さない。

### 現在のAnalyzer（Issue #6）

`dist/analysis.js` の `analyzeAudio(AudioBuffer, {signal, onProgress, yieldTask})` が上記Analysisを返す。AudioContext、DOM、再生、スタイルには依存しない。`yieldTask` の既定値はUIへ処理を譲るタイマーで、テストでは待機方法を置き換えられる。読取専用の入力に対し同じ順序で計算し、結果を利用側で書き換えない。

識別方式は `pcm-f32-block-sha256-v1`。各チャンネルを65,536サンプルごとに区切り、Float32のバイト列をSHA-256でハッシュする。チャンネル順・ブロック順の32バイトハッシュ列の前に、解析版・方式名・サンプルレート・全サンプル数・チャンネル数・ブロック長を含むJSONのUTF-8を付け、全体を再度SHA-256にする。最後の部分ブロックを含め、全PCMを対象とする。Float32のバイト順は実行環境のものを使い、同一環境内の再現性を対象とする。

`trackKey` は `pcm-sha256-v1:` と最終ハッシュの16進文字列。seedは同じ最終ハッシュの先頭32ビットをbig-endianで数値化する。ファイル名・現在時刻・ランダム値を加えない。解析版や識別方式を変えるとキーとシードも変わるため、旧版と同じ作品になるとは約束しない。

ブラウザ標準のWeb Cryptoを使い、デコードPCM全体の追加コピーを作らず、ブロック単位で処理する。全チャンネルのフィルター状態は別々に持ち、区間のエネルギーを統合する。解析・平滑化は120フレーム単位でUIへ処理を譲り、ハッシュの前後も中止を確認する。ピーク探索は逐次更新し、配列を関数引数へ展開しない。

`AudioEngine.analyze()` は `{buffer, analysis, features: analysis.frames, seed: analysis.seed}` を準備し、`commit()` が確定する。解析値をコピーせず `AudioEngine.analysis` と `features` を再利用する。フィルターは [W3C Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/) の低域・高域通過係数に基づく。入力PCMの非有限値は特徴計算時に0として扱い、最終連続値を有限の0〜1に保つ。

## 固定ステップと時刻

描画は30ステップ/秒。0秒は初期背景のみ。floor/ceilの前に共通timing.jsで整数境界の浮動小数点誤差を補正する（閾値は仕様書の再現性節）。時刻 `t < duration` の描画済み数を `floor(t*30)`、曲末では `ceil(duration*30)` とする。ステップ `k` はframes[k]を一度消費して描き、最後のステップのdtは `min(1/30, duration-k/30)` とする。シーク・PNG・録画もこの同一規則を使う。

再生時の目標時刻は音声時計から取得し、requestAnimationFrameの回数や実時間の差分を作品の時間として使わない。処理落ち時は不足ステップを順に計算する。復元は分割処理でUIを応答可能に保ち、計算中に作品内時間を進めない。過負荷時の録画はフレームを黙って捨てて成功扱いにせず、#16の測定に基づく遅延検出で中止する。

## スタイル契約と3層

```text
StyleDefinition { id, version, create() }
StyleInstance {
  reset({ width, height, seed, settings }),
  step({ frameIndex, time, dt, features, layers }),
  snapshot(), restore(state), dispose()
}
```

`create()` は独立インスタンスを返す。内部状態は乱数状態、粒子、曲線の前位置、位相、寿命等。外部の現在時刻・Math.random・UIを直接参照しない。設定は不変のコピーを渡し、値変更は新しい生成世代としてリセットする。乱数は各インスタンスが固定シードの疑似乱数器を持ち、消費順を固定する。

- 背景層：解像度とテーマから作り、設定が変わるまで保持する。
- 描画層：軌跡を蓄積する。減衰はdtに基づく係数で適用する。
- 演出層：現在のステップの粒子・発光・波紋を描き直す。粒子の運動状態自体はStyleが保持する。
- 合成先：背景→描画→演出の順で合成する出力Canvas。プレビューはこのCanvasをCSSで縮小し、PNGと録画は同じ合成先を使う。表示倍率で内部解像度や描画条件を変えない。

3層は同じ内部解像度で作る。スタイルは渡された描画先だけに書き込み、合成順序を変更しない。PNG完成アートも終端の合成結果を使い、別経路の静止画描画を用意しない。

### 現在の描画基盤（Issue #7）

`dist/renderer.js` の `Renderer`（版 `sc-renderer-4`）が3枚の内部Canvasと合成先を所有する。共通の刻み・曲末計算は `dist/timing.js` に集約し、解析と再生制御も同じ30Hzを参照する。

| API | 動作 |
| --- | --- |
| `reset(seed, {trackKey, analysisVersion, duration})` | 3層と内部状態を初期化し、背景を合成する。曲末の端数dtもこのdurationから決める |
| `configure(patch, [width,height])` | 共通設定・解像度を検証して初期化する。出力Canvasのサイズを外から直接変更しない |
| `step(features, {present:true})` | 1ステップ進め、必要なら合成する。曲末以降は更新せずfalseを返す |
| `present()` | 背景→描画→演出を出力Canvasへ合成する。内部時間・乱数は進めない |
| `snapshot()` / `restore(snapshot)` | 3層の独立した描画面コピーとスタイル状態・乱数・次のフレーム番号を保存/復元する |
| `dispose()` | 有効スタイルを終了し、内部3層の描画面を解放する。保存済みスナップショットは所有者が管理する |

描画層の減衰はエンジンが `destination-out` で行う。1/30秒の透明化率0.018を4ステップ単位でまとめ、`1 - (1 - .018) ** ticks` を適用する。ticksはframeの剰余と今回dtから計算し、終端では4未満でも端数を含めて反映する。減衰の位相は保存済みframeから再現できる。8ビットの丸めで灰色が残る量を抑えるための処理であり、完全に透明になる保証ではない。演出層は毎ステップ透明に戻す。背景層はスタイルに渡さない。スタイルにはdrawing/effectsの2つのコンテキストを渡し、各更新の前後をsave/restoreで囲む。特徴値と共通設定は読み取り専用のコピーを渡す。

スタイル登録は `dist/styles/index.js` の定義表で行う。定義はid/version/create、生成したインスタンスはreset/step/snapshot/restore/disposeを持つ。エンジン内にスタイル名による描画分岐を追加しない。`dist/styles/organic.js` は既存曲線の独立した実装で、前の点・発光の寿命・LCG乱数状態を自分で所有する。発光は演出層に最大64個保持し、寿命で消す。テーマの色と背景は `dist/themes.js` で共有する。

Issue #8では有機的曲線を `organic-2` に更新する。固定時間の単純な位相ではなく、`travel += dt × (0.16 + 0.28×mid + 0.18×intensity) × (0.6 + 0.4×strength)` の移動時計を持つ（値は反応設定適用・上限制御後）。目標位置をdtに基づく慣性で追い、急な広がりの変化を短い曲線でつなぐ。これは描画シミュレーションであり、解析値の平滑化を再実行するものではない。

初期位相と7本の配置はLCGから生成し、同じシードで再生成できる。highに応じたきらめきの発生余り `detailCredit` と移動時計 `travel` をlast/pulses/randomStateに追加して保存する。復元時はこれらの有限値・範囲を検証し、乱数の消費順も復元する。版が変わるためorganic-1のスナップショットはキー不一致として拒否する。

描画層と演出層はsource-overで色を重ね、加算の飽和を避ける。低音は描画領域の広がり、高音は描画層の小さな点、ビートは演出層の発光へ割り当てる。発光数はintensityにより1回2〜7個、最大64個、寿命0.4〜0.8秒。画面の余白・線幅・発光サイズは短辺を基準にする。

### 幾何学スタイルと選択UI（Issue #9）

`dist/styles/geometric.js` の `geometric-1` を登録表に追加する。RendererやAnalyzerに幾何学専用の分岐は追加しない。UI用に各定義へlabel/description/symbolを持たせ、app.jsが登録表から選択ボタンを作る。選択状態はrenderer.settings.styleを正とし、aria-pressedとチェック表示へ反映する。読込中の無効化と現在位置の再計算は既存のコントローラーを使う。

形は正規化した内トロコイド `x=(1-r)cos(t)+d cos((n-1)t)`, `y=(1-r)sin(t)-d sin((n-1)t)` に基づく。nは整数、r=1/n、d<=0.95rで、正規化した振幅は1以下に収まる。シードで基準nを5/7/9から選び、3本にn/n+2/n-1を割り当てる。短辺基準の半径は低音・intensityで変え、dtに基づいて追従させる。全体を回転し、ビートでは0.28秒で減衰するflashを使って回転速度を上げる。

角度は3本それぞれが0〜2πで循環し、全体のrotationも循環する。曲線側の係数が整数のため、一周する境目で位置が飛ばない。angles/rotation/radius/flash/last/rings/randomStateを保存し、有限値と範囲を検証して復元する。静的な形の係数と色の選び方は同じシード・設定から再生成する。

描画層は3本の色付き軌跡、演出層はビートの円と現在位置の小さな発光を担当する。円は寿命0.5〜0.8秒、最大24個。形と円の振幅に余白を取り、3比率の最大反応でも収まるようにする。蓄積/減衰と合成先は共通エンジンに任せる。

複数の固定ステップを処理するときは途中のpresentを省略し、必要なタイミングで一度だけ合成できる。プレビューとPNGは同じ出力Canvasを使う。録画接続は#15で行う。シーク用スナップショットの自動キャッシュはまだ使わず、#14でメモリ・性能とともに導入する。

## スナップショットと復元

保存対象は背景の再生成条件、描画層の画素、Style内部状態、乱数状態、次のステップ番号。演出層も内部状態から無更新で再描画できない場合はその画素を保持する。画像だけの復元は粒子や乱数を一致させられないため禁止する。

キャッシュキーはtrackKey、解析版、描画/スタイル版、シード、全設定、解像度から作る。曲、設定、比率、版が変われば該当キャッシュを無効化する。直前の有効スナップショットを復元して目標まで更新する。有効なものが無ければ0から再計算する。

1枚のRGBA画素の概算は幅×高さ×4バイトで、複数層・状態を含めると増える。固定間隔で無制限に保持しない。#14で時間/メモリを計測して上限と間隔を決め、上限超過は古いキャッシュを捨てる。最適化しても未キャッシュ時と同じ結果でなければ採用しない。

現在のスナップショットは、半透明画素をgetImageData/putImageDataで数値配列へ往復させず、同じサイズのCanvasへcopy合成した描画面を保持する。数値配列の往復では本環境の実測で画素差が出たためである。これはメモリ内のオブジェクトであり、JSON化やスナップショット全体のstructuredClone、永続保存を行う形式ではない。styleStateのみを複製可能なデータにする。

復元キーは描画版、スタイル版、シード、全設定、曲識別/解析版/長さ、解像度を含む。異なるキーや不正なフレーム・描画面・スタイル状態は拒否し、検証と一時コピーを済ませてから有効状態を置き換える。スナップショットの描画面は現在の3層と共有しない。所有者は破棄時に参照を外し、必要なら描画面のサイズを0にして解放する。

全描画面の2Dコンテキストに `willReadFrequently:true` を一貫して指定する。これは読み取り用途のヒントであり、すべてのブラウザの内部実装を固定する指定ではない（[HTML Standard](https://html.spec.whatwg.org/multipage/canvas.html#concept-canvas-will-read-frequently)）。本環境ではこの統一後、合成の頻度や復元前後の画素比較が一致した。発光は重いパス単位のぼかしを避け、多重ストロークと小さな放射グラデーションで表現する。再現性は同一環境での検証範囲に限り、他ブラウザと長曲の性能は後続Issueで確認する。

## 状態とキャンセル

操作画面は既存Controller/PNG/Videoの状態から保存不可の理由を作り、usability.jsのFlowFocusで操作開始・終了時のフォーカスを扱う。処理の進捗通知のたびにフォーカスを変更しない。無効になった開始ボタンから中止へ、終了時に保存先または再試行へ移すが、別の操作へ移った利用者のフォーカスは保持する。設定/シーク復元の開始元が有効ならそのまま保つ。キーによるシークも既存のController.seekへ渡し、別の再生位置状態を持たない。

コントローラーは読込・復元・出力の実行世代を持つ。非同期処理は描画・音源確定・状態通知の前に世代と中止フラグを確認する。最後の要求だけを有効にし、設定変更や曲差替えで古い処理がUIを更新しない。

音源差替えは候補のデコード/解析を完了してから確定する。復元中の新要求は旧要求を無効化する。録画中は曲や設定を変えず、仕様書の排他表に従う。録画・完成PNG生成前の位置を保存し、終了/失敗/中止後はその位置へ復元して停止する。

リセットは画素と内部状態の両方を消去する。停止は音声位置を保存し蓄積を保持する。曲末は最後の短いステップまで完了してから完成状態にする。

## 音声と出力経路

```text
AudioBufferSource → 共通の音声出力
                      ├→ スピーカー
                      └→ 録画用MediaStreamAudioDestination
合成Canvas → 映像トラック ─┐
録画用音声トラック ──────┴→ MediaRecorder → WebM
```

必要API・MIME・音声/映像トラックを事前確認し、録画できない環境では録画ボタンに理由を表示する。通常再生ノードをそのまま流用して二重再生せず、専用の再生セッションを作る。準備完了後にMediaRecorderと曲の開始を揃え、音声時計を映像更新の基準とする。曲末フレームの合成後に録画終了を要求し、最後のdataavailableとstopを待って保存する。開始・停止の具体的なタイミングと負荷の許容条件は#15/#16の検証で確定する。

録画は実時間方式であり、MediaRecorderをオフラインのフレームエンコーダとして扱わない。タブ非表示・追従できない遅延・トラック停止は制御された中止とする。全ての終了経路で音源、接続、録画トラック、イベント、タイマー、不要なBlobとURLを解放し、通常制作のAudioContext自体は継続利用できるようにする。

PNGは同じ描画セッションから合成CanvasをBlobへ変換する。完成PNGのために再計算する場合も独立セッションまたは元状態の確実な退避/復元を使い、再生位置を失わない。

Issue #17では現在/完成のどちらにも独立したRendererを使う。png.jsのPngExporterが一時停止時刻を固定し、元Rendererのスタイル登録・Canvas生成方法・設定・シード・解析情報を引き継いだ出力面を所有する。現在の解析フレームを使い、音声再生や別の解析を開始しない。8ms目安/最大120ステップでyieldし、中止を確認する。最後のpresentが終わったCanvasだけをtoBlobするため、画面のUIを含まない。

生成中はStudioController.exportingを取得し、VideoExporter.canStartもこのフラグを確認する。元の描画面・チェックポイント・音声位置を変更しないため、終了時の元位置再描画は不要。中止・期限超過・ページ終了後の遅いtoBlobは結果を公開せず、job固有の中止信号と一度だけの完了処理で退ける。変換の30秒タイマーは全終了経路で解除し、出力Renderer/Canvasを解放する。成功URLは保存リンクのため保持し、再生成・曲読込・disposeで解放する。実装と例外/画素確認は[確認記録](issue-17-validation.md)を参照する。

## 検証と実装への移行

| 対象 | 検証 |
| --- | --- |
| Analyzer | 合成音・無音・逆相・強弱で有限値と帯域、イベント、再解析の一致 |
| Style | 同じ入力列で状態と画素が一致、乱数の復元、reset/dispose |
| RenderEngine | 順再生とシーク、0秒・短い最終区間、全比率、蓄積/減衰、キャッシュ有無の一致 |
| コントローラー | 連続読込・連続復元・設定変更・失敗・キャンセル・終端からの再生 |
| 出力 | 音声/映像、解像度、先頭/中間/終端の同期、最終画面、全終了経路の資源解放 |

同一ブラウザ環境で固定入力と設定を比較する。異なるブラウザのピクセル差は再現性不具合と即断せず、各環境内の一致と出力条件を確認する。テスト用音源は合成または公開権利を確認したものを用いる。

移行順は #5 の状態管理、#6 の解析、#7 の描画基盤、#8〜#12 の個別表現と設定、#13〜#17 の再現性・性能・出力。最初から全面改修せず、各PRで旧機能との確認条件を残す。新スタイルは共通契約と登録だけで追加できることを幾何学・粒子で検証する。

## 粒子スタイルの実装（Issue #10）

`styles/particles.js` を登録表へ追加し、解析器・描画エンジン・コントローラーにスタイル分岐を増やさない。固定刻みで3つの発生源、中心への引力、旋回、低音の外向き加速度、減衰と速度上限を計算する。短辺4%（最低2px）の内側で反射し、256個を超える発生は捨てる。加算合成を避け、発光の勾配計算を32個に制限する。

保存対象は時計、発生数の端数、各粒子の位置・速度・年齢・寿命・半径・色・音量・高音・位相・発光フラグ、乱数状態。restoreは全値を検証してから置換し、不正値で部分更新しない。resetでシードから再生成し、disposeで粒子を解放する。静的な初期位相と色オフセットは同一設定のresetで再構築する。共通の描画面スナップショットと合わせて復元する。登録定義のmaxTransientは比較ページでスタイルごとの状態上限を検証するための値である。

## 水彩スタイルの実装（Issue #11）

`styles/watercolor.js` を登録表へ追加する。描画基盤に水彩専用の分岐は持たせない。3つの発生源を固定刻みの音楽時計で移動させ、6〜12回/秒を基準に盛り上がりと反応設定で調整したスタンプを描く。半径は短辺で制限し、3次・5次の正弦波で輪郭を変形させた48分割の塗りと、放射状グラデーションで柔らかい縁を作る。高音は1スタンプ最大6点の顔料。source-overと色相の維持により全面の白飛びを抑える。

ビートのにじみは演出層で拡大し、1.1〜1.6秒で消える。最大18個。時計・スタンプ発生数の端数・にじみの位置/年齢/寿命/半径/色/位相/音量・乱数状態を保存する。resetで同じシードの初期位相と色オフセットを再構築する。restoreは全値を検証してから置換、disposeはにじみを解放する。無音では時計と既存演出だけを進め、新しい顔料や乱数消費を発生させない。背景と蓄積/減衰、合成とPNGは共通エンジンへ委ねる。

## 設定パネルの統合（Issue #12）

`settings-ui.js` のSettingsPanelがスタイルボタンの生成、テーマ色見本、反応入力、比率、選択表示を担当する。app.jsはパネルへStudioController.configureを渡し、画面更新時にrendererと操作可否を渡す。描画設定のコピーを別に保持せず、操作中の反応値だけを一時的に保持する。色相はthemes.js、スタイル名と説明は登録表、比率と出力サイズはaspectRatios定義を使う。色見本はテーマ変更時だけ作り直す。

StudioController.canConfigureで読み込み中の変更を拒否する。configureは変更のない要求を早期終了し、既存復元や再生開始待ちも中断しない。変更がある場合は従来の世代・中止処理を使う。Renderer.configureの検証失敗時は従来の描画を保持し、必要なら再生を継続してUIへ通知する。復元中の失敗要求は進行中の正しい復元を取り消さず、その完了まで再生を待つ。PNG可否は既存のcanSaveを使う。動画と完成PNGの排他状態は#15/#17で追加する。

設定から描画への統合検証は、実際のHTMLから作るパネル・実コントローラー・実Rendererを組み合わせ、実Canvasで行う。テスト用音声時計により時刻を固定し、全216通りを別Rendererでの冒頭からの生成と比較する。通常画面の音声再生は別途確認する。

## 再現性の統合検証（Issue #13）

解析器はフレーム数と平滑化の端数dtをtiming.jsから取得する。音声時計は `offset + (currentTime - started)` の順に計算する。整数境界補正が解析と描画の両方へ影響するため、解析版3・描画版4へ更新し、旧版キーを拒否する。個別スタイルの式と固定乱数は変更しない。

reproducibility-browser.htmlは共通PCMを2回解析し、音声出力だけを制御可能な時計へ置き換えた実AudioEngine・StudioController・Rendererで検証する。順次更新、大幅な時刻ジャンプ、停止中の時計進行と再開、前後へのシーク、スナップショット、設定を変えて戻す操作、別名再読込を比較する。比較の参照Rendererは同じ特徴列を冒頭から順に消費する。合成と3層それぞれの全RGBA、および状態JSONを厳密比較する。出力と状態のSHA-256も記録し、許容する画素差は0。PNG比較図の縮小は表示用であり、一致判定は縮小前の画素で行う。

## シークの保存状態と分割処理（Issue #14）

CheckpointCache（checkpoints.js）が保存面の所有とLRU破棄を担う。キーはRenderer.snapshotKeyをそのまま使用し、1つのキーだけを保持する。各エントリーはsnapshot・見積りbytes・最終利用順を持つ。450ステップごとと復元完了時にrememberを呼び、同じフレームの重複は作らない。0秒や1件でも保持上限を超える解像度では保存しない。48MiBと4件の両方を満たすまでLRUのCanvas寸法を0へ戻して解放する。状態の見積りはJSON文字数×2、Canvasはwidth×height×4×3とする。ブラウザ全体のメモリ計測値ではない。

制作コントローラーは、同じキーでtarget以下の最も進んだスナップショットと現在のframeを比較する。現在frameがtargetを超えていて保存状態も無ければリセットする。読み込み成功時は同じPCMでも一度全保存を解放し、失敗・中止時は前の曲の正しい状態を再利用できる。設定変更でキーを同期し、以前の保存面を解放する。復元拒否時は全保存を破棄して0から計算する。描画エンジンとスタイルの式は変えず、版もsc-renderer-4のままとする。

復元開始時はUI通知後に一度処理を譲る。以降も8msの目安か120ステップで合成・進捗通知・yieldを行い、再開直後に中止世代を確認する。snapshotのコピーと単一stepは非分割。進捗は再利用開始frameからtargetまでの計算分に対して求める。lastRestoreは開始frame・計算ステップ数・キャッシュ利用・分割数・経過時間を検証用に持つ。UIは進捗・移動先・cancelRestoreを接続し、中止は既存restartを使って0秒へ戻す。古い処理は進捗や再生意図を更新しない。

再訪時の削減を優先した方式で、初回は保存コピーと細かなyieldの費用が加わる。15秒間隔は近い位置の後方シークで計算量を抑えるために選び、全曲の全時刻を保持する方式にはしない。測定と再実行方法はissue-14-validation.mdを参照する。

## WebM出力の実装（Issue #15）

video.jsのVideoExporterが録画専用セッションとMediaRecorderを所有する。AudioEngine.createRecordingSessionは共有AudioContext上に別のBufferSourceとMediaStreamAudioDestinationを作り、通常sourceを使わず音声時計・開始・停止を提供する。Sourceはスピーカーと録画出力へ一度ずつ接続する。共有のAudioEngine.timeは開始前の位置のまま保持し、映像更新は専用セッションのtimeから求める。

StudioController.exportingはユーザー操作の入口とtickを止め、canConfigure/canSaveにも反映する。内部のrestoreは終了後の元位置復元のために使用できる。VideoExporterはpreparing→recording→finishing→restoring→ready/error/idleを管理し、job参照とfinishingで古いイベントと二重終了を拒否する。破棄後の遅い完了もUIへ通知しない。

CanvasをcaptureStream(0)で取り込み、音声1本と映像1本をMediaStreamにまとめる。開始には両方のメディア供給が必要な実装があるため、start呼出し後に最初のrequestFrameと100ms後の音声開始を予約し、開始イベント待ちと描画ループを並行する。ループは音声時計の目標ステップまで共通Rendererを進めて合成後にrequestFrameする。終端で2回の画面更新を待ち、stop後の最終dataavailableとstopイベントを受けてBlobを作る。開始・停止イベントには期限を設け、途中停止や終了時のエラーでも成功ファイルを公開しない。

終了はRAF・タイマー・イベントを解除し、専用Source/接続/全録画トラックを停止する。中止はチャンクを破棄する。成功BlobとURLだけを保持し、元位置の復元を終えてからUIを解放する。元位置へ復元できなければ成功表示にせず、利用者へ理由を示す。pagehideは待機せず録画資源とURLを解放し、共有AudioContextは録画処理からcloseしない。

ブラウザ試験は同じ実装で合成音を録画し、WebMのTrackEntryを解析してVP8映像とOpus音声、解像度を確認する。音声をdecodeAudioDataで再デコードしてRMSを測り、video要素で最後まで再生する。元の位置の画素・内部状態も比較する。同期の100ms目標、全スタイル×全比率の横断確認、長曲の性能は#16/#18で測る。

APIの根拠は[Media Capture from DOM Elements](https://www.w3.org/TR/mediacapture-fromelement/)と[MediaStream Recording](https://w3c.github.io/mediacapture-record/)を参照する。

## 保存動画の測定（Issue #16）

製品のRenderer・音声時計・VideoExporterをそのまま使い、試験専用beatマーカーで独立した同期測定を行う。試験用webm-inspect.jsがコンテナ時刻・CodecDelay・Colourを読み、WebCodecsへ明示して実際の圧縮映像と音声をデコードする。画質は共通Rendererの参照画像と全画面・前景・端を比較する。コンテナの色指定を省略したデコードを参照にしない。時刻付きデコード・測定コードはtests内に置き、配信用distには追加しない。

3比率の同期、4スタイル×3比率の冒頭付近・中間・最終画面、450msの処理停止を実測した。同期と画質の許容値・実測値・参照時刻候補の扱いは[確認記録](issue-16-validation.md)を正とする。実際の非表示通知は自動操作環境で発生せず未確認。録画中止の6ステップ閾値は同期精度の保証へ置き換えず、長曲・通常ブラウザ・他環境は#18で確認する。
