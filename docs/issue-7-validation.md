# Issue #7：3層描画基盤と状態復元の確認

## 実装した範囲

- 背景・蓄積描画・一時演出を内部Canvasに分離し、出力Canvasへ同じ順序で合成する。
- 共通設定と登録表で単独スタイルを選ぶ。既存の有機的曲線を独立したスタイルへ移す。
- 曲線の前の点、発光の寿命、固定シードの乱数状態をスタイルが所有し、リセット・復元する。
- 背景を保ったまま描画層を蓄積または減衰させ、演出層だけを毎ステップ描き直す。
- 30Hzの時刻と曲末の端数dtを共通化し、終端では完成した合成画面を保持する。
- 3層と内部状態を保存/復元するAPIを追加する。自動キャッシュによるシーク高速化は#14の範囲。
- 更新と合成を分け、一括処理中の不要な合成を省く。初期プレビューの計算量も減らす。

同時に複数スタイルを重ねる機能、幾何学・粒子・水彩そのもの、曲線の音楽反応全体の仕上げ、録画、完成アート専用PNG生成は今回の対象外。intensityは共通入力で受け渡せるが、曲線の表現への利用は#8で行う。

### 比較で見つけた問題と対処

当初は半透明画素をImageDataへ変換して保存し、戻すと一部RGBに差が出た。Canvas面をそのまま複製する方式へ変更した。さらに描画・コピー・出力のコンテキスト設定を統一した後、毎ステップ合成と一括合成を含む26ケースが一致した。内部のCPU/GPU選択そのものは計測しておらず、すべての環境で一致するとは保証しない。

設定統一後に通常画面の描画負荷が増えたため、曲線のぼかしを多重ストロークへ、発光を小さな放射グラデーションへ変更した。初期プレビューは180ステップ・発光なしに減らした。最終版で通常画面のデモ読込、再生、5秒へのシーク、Oceanテーマ、減衰、1:1への変更、曲末の完成表示を確認した。初回版の長い画面読込も再発しなかった。これは操作確認であり、フレームレートや最大曲長の性能保証ではない。
